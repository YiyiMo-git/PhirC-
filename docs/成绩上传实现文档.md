# 成绩上传：实现文档

> 面向对象：接手/复用这套实现的开发者。
> 目标：把「打完一局官方谱面 → 把成绩传给 Phira 官方服务器」这条链路讲清楚，
> 包括数据格式、编码算法、代码位置、开启条件、以及已经验证过的事实和仍然存疑的地方。

## ⚠️ 保密提示

**本文档包含与服务端约定的 HMAC 密钥（见 §4）。**
这套密钥是官方客户端的，无法轮换；配合本文档的算法，任何人都能构造出服务端接受的成绩记录。
**请勿公开传播本文档，也不要放进任何公开仓库。**

公开仓库（`publish/phira-mod-clean` → GitHub `PhiCraft/Phira-Mod-New`）里**不包含**
本实现与本文档，见 `上传成绩逆向笔记.md` §25 的发布红线。

## 1. 一句话概括

客户端把一局的结算数据序列化成 **92 字节**，经过「自定义字节变换 → HMAC 签名 → deflate → base64」
得到 **180 字符的 token**，连同谱面 id 一起 `POST /play/upload`。

```text
92 字节记录
  │  custom_enc（补到 96 字节 + 块变换，无密钥）
  ▼
96 字节密文
  │  ‖ HMAC-SHA256(静态密钥, 96 字节密文)     ← 尾部 32 字节
  ▼
128 字节 payload
  │  raw deflate（level 0，即不压缩）
  ▼
135 字节
  │  base64
  ▼
180 字符 token  →  POST /play/upload
```

## 3. 92 字节记录布局

| offset | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 版本常量 `3` |
| 1..4 | u32 **LE** | player id |
| 5..8 | u32 **BE** | 谱面 id（注意是**大端**） |
| 9..16 | f64 **LE** | 判定误差方差 variance（见 §5） |
| 17..20 | u32 LE | 保留。9 个真实样本恒为 0（**遗留项，见 §8**） |
| 21..23 | 3×u8 | 官方放「7 位值 ×2 + 布尔标志」，**服务端不校验**，本实现填 `00 00 00` |
| 24..27 | u32 LE | 保留，样本恒为 0 |
| 28 | u8 | 常量 `0xd8` |
| 29..32 | u32 LE | max_combo |
| 33..36 | u32 LE | counts[0] Perfect |
| 37..40 | u32 LE | counts[1] Good |
| 41..44 | u32 LE | counts[2] Bad |
| 45..48 | u32 LE | counts[3] Miss |
| 49 | u8 | 速度 × 100（1.0 倍速 → 100） |
| 50..81 | 32×u8 | **官方谱面文件原始字节**的 SHA-256 |
| 82 | u8 | 常量 `0x74` |
| 83 | u8 | 常量 `0xd2` |
| 84..87 | u32 LE | num_of_notes |
| 88..91 | u32 LE | 保留，样本恒为 0 |

`custom_enc` 会把 92 字节补到 96 字节，填充值是 `92 & 0xf = 0x0c`，即 `92..95 = 0c 0c 0c 0c`。

## 4. 编码算法

### 4.1 custom_enc（无密钥的确定性变换）

```rust
fn custom_enc(plain: &[u8]) -> Vec<u8> {
    let pad = (plain.len() & 0xf) as u8;
    let new_len = (plain.len() & !0xf) + 0x10;   // 92 → 96
    let mut data = plain.to_vec();
    data.resize(new_len, pad);

    for block in data.chunks_exact_mut(16) {
        zeta_transform(block);   // 4 维子集和
        bitrev_permute(block);   // 4-bit 位反转置换
    }
    data
}
```

* `zeta_transform`：`out[i] = Σ_{j ⊆ i} in[j] (mod 256)`（i、j 为 0..15，`j ⊆ i` 指按位包含）
* `bitrev_permute`：块内 `i ↔ rev4(i)` 互换，`rev4` 是 4 bit 位反转（0→0, 1→8, 2→4, 3→12, …）
* **没有密钥**，纯确定变换，因此可以完整复现。

### 4.2 HMAC 密钥（⚠️ 保密）

```text
KTCfLeu6d6gq957WOEyj-light
```

26 字节 ASCII。在官方二进制里是一段混淆过的常量，异或还原后即为此值。
消息是 **custom_enc 输出的 96 字节密文**（不是明文），算法为标准 HMAC-SHA256，取完整 32 字节。

### 4.3 deflate

**必须是 raw deflate（无 zlib/gzip 头），且用 level 0（不压缩）。**
官方客户端就是 level 0，所以 128 字节 payload 压成 135 字节（stored block 的开销），
base64 后正好 180 字符 —— 这也是判断"是不是官方格式"的一个快速特征。

用别的压缩等级服务端也能解，但没必要引入变量。

### 4.4 参考实现（Python，用于验证/对拍）

见 `docs/rev/encode_upload.py`（`--verify` 能对全部抓包样本逐字节复现）与
`docs/rev/decode_upload.py`（反解 token）。

## 5. variance 怎么算（最容易搞错的地方）

记录 offset 9..16 写的是**判定时间误差的方差**：`Σ diff² / 判定次数`。

每次判定调用 `JudgeInner::commit(what, diff)`，其中 `diff` 的取值规则（来自上游源码）：

| 情况 | diff |
|---|---|
| Miss | `0.25`（合成值，精确常量） |
| Drag / Flick 音符（任意判定） | `0.0`（合成值，没有真实计时） |
| Hold 的自动判定 | `0.0` |
| 其它（真实计时） | `(命中时刻 - 音符时刻) / 速度` |

**实现上必须把累加放在 `commit()` 内部**：

```rust
self.diff_sum_sq += diff * diff;
self.diff_count += 1;
```

只有这样，上面那些合成值才会按官方语义同时进入分子和分母。
（自己另算一遍一定会算错：分母是**判定次数**，不是只统计真实计时的那些。）

验证依据：一局全 Miss 的方差**精确等于 `0.25² = 0.0625`**；
其余样本用 `variance × n - Miss数 × 0.0625` 反推出的真实计时标准差都是 27–70 ms 的合理人类值。

## 6. 上传请求

```http
POST https://phira.5wyxi.com/play/upload
Authorization: Bearer <access token>
Content-Type: application/json

{"chart": <chart id>, "token": "<180 字符 base64>", "chartUpdated": "<RFC3339 或 null>"}
```

响应：

```json
{"id": 123456789, "expDelta": 0.0, "newBest": false, "improvement": 0, "newRks": 0.22890516}
```

失败时返回 `{"code": "...", "error": "..."}`，`Client::post` 会把 `error` 原样抛到界面上，
方便排查（例如未鉴权是 `HTTP 401 {"code":"UNAUTHENTICATED","error":"invalid token"}`）。

## 7. 什么时候才会真的上传

两个条件必须同时满足：

**（1）用户在设置里打开了「上传成绩」** —— 对应 `Config::upload_record`（**默认 `false`**）。
设置页有完整的知情同意流程：首次打开会弹协议，同意后才置为 `true`，
并可一键切到"可上传配置"（清 mod、速度回 1.0、关离线模式与键盘游玩）。

**（2）这一局是"正式局"**（`prpr/src/scene/game.rs` 里判断，与 `phira` 侧的 `rated` 逐项一致）：

```text
!config.offline_mode                 // 不是离线模式
&& !config.mods.intersects(UNRATED)  // 没有 UNRATED mod（自动游玩/无着色器/无连击分/全屏判定/血条）
&& !config.use_keyboard              // 不是键盘游玩
&& config.speed >= 1.0 - 1e-3        // 速度不低于 1.0
&& 已登录 && 谱面是官方谱面（有 id）
```

> `rated` 只控制「本局成绩不计入排行」这句提示，但**它必须和引擎侧条件逐项一致**，
> 否则会出现"没提示不计入排行、但成绩其实没上传"这种极难排查的情况。

## 8. 注意事项与遗留

1. **谱面哈希必须用官方谱面文件的原始字节**做 SHA-256。
   不要用解析后重新序列化的结果 —— 服务端会判谱面不匹配直接拒绝。
   代码里取的是 `GameScene::chart_bytes`（`load_chart()` 本来就返回原始字节）。
2. **chart id 是大端**写入，player id 是小端 —— 别写反。
3. **offset 17..20 目前写 0**（9 个真实样本恒为 0）。
   早期笔记猜过它可能是 `config.mods`，但**没有样本支持**。
   要定案：抓一局带 rated mod（例如 `FLIP_X`）的上传样本，看这 4 字节是否变成非零。
4. **offset 21..23 填 0 是安全的**：实测把真实样本的这三个字节改成 0 后重传，服务端照样接受
   （HTTP 200），说明它不参与校验。
5. 官方随时可能调整格式；改动后本实现会失效（表现为服务端拒绝或成绩不入库）。
6. **调试请用小号**：上传的是官方排行榜，异常成绩可能触发风控。
