## 1. 风格定义（先定数值，不然每次都在"再调调"）

| 维度 | 取值 |
|---|---|
| 基础色 | 深色底 `#0B0D12`；玻璃面板 `rgba(255,255,255,0.06~0.10)` |
| 高光边 | 1px 内描边 `rgba(255,255,255,0.18)`，顶部略强（模拟上方光源） |
| 模糊 | 背景降采样 ×1/4 后做**可分离高斯**两趟，σ ≈ 6~10（1/4 尺度下等效屏幕 σ≈24~40） |
| 圆角 | 面板 16、卡片 12、按钮 10、小控件 8（单位：UI 逻辑像素） |
| 间距 | 8 的倍数：8 / 16 / 24 / 32 |
| 文字 | 主 `rgba(255,255,255,0.92)`、次 `0.62`、禁用 `0.35`；字号 4 档 |
| 强调色 | 跟随当前谱面难度色（章节色）作为 accent，玻璃面板边缘透出 accent 的微光 |
| 动效 | 面板进出：180ms `cubic-bezier(0.22, 1, 0.36, 1)`；悬停：120ms 缩放 1.0→1.02 |
| 噪点 | 玻璃上叠一层极淡 noise（`core/shaders/noise.glsl` 已存在），消除"塑料感" |

**高级质感的三条真正来源**（优先级从高到低）：
1. **有层次**：不只是模糊 —— 面板后面要有「背景 → 中度模糊 → 玻璃 → 内容」的纵深；
2. **有光**：顶部内描边高光 + 面板底部投影（`ui/shadow.rs` 的解析阴影直接用）；
3. **有节奏**：统一圆角/间距/动效曲线，比任何单点特效都重要。

## 2. 技术方案

### 2.1 可以复用的（已存在，不要重写）

| 已有 | 位置 | 用途 |
|---|---|---|
| 圆角裁剪材质 `RR_MATERIAL` | `prpr/src/ui/shadow.rs:24` | 解析式圆角 alpha 遮罩，`clip_rounded_rect()` |
| 解析式圆角阴影 `SHADOW_MATERIAL` | `prpr/src/ui/shadow.rs:21` | 面板投影，直接拿来用 |
| `MSRenderTarget` | `prpr/src/core/render.rs` | 多重采样 RT，已有 `input/output/old` 三缓冲 |
| `RenderTargetChooser` | `prpr/src/scene.rs:367` | 场景可被渲染到指定 RT（取背景的关键） |
| `circle_blur.glsl` / `noise.glsl` | `prpr/src/core/shaders/` | 模糊与噪点素材 |

⚠️ 所有 shader 都是 **`#version 100`（GLES2）** —— 没有 `textureLod`、没有整数纹理、
循环必须有常量上界。写新 shader 要按这个来。

### 2.2 要新增的

```text
prpr/src/ui/theme.rs     ← 设计 token：颜色/圆角/间距/字号/时长/缓动（单一真源）
prpr/src/ui/glass.rs     ← 玻璃原语
prpr/src/core/render.rs  ← 加一个 1/4 降采样 RT（backdrop buffer）
```

`glass.rs` 的内容：

```rust
// 1) 两趟可分离高斯（H / V），在 1/4 分辨率的 backdrop RT 上做
static BLUR_H: Lazy<Material>;   // uniforms: direction(vec2), radius(f1), sigma(f1)
static BLUR_V: Lazy<Material>;

// 2) 玻璃合成：模糊图 × 圆角遮罩 × tint × 顶部高光 × 噪点
static GLASS_MATERIAL: Lazy<Material>;

/// 每帧（或背景变化时）调用一次：把背景画进降采样 RT 并模糊好
pub fn update_backdrop(ui: &mut Ui, draw_bg: impl FnOnce(&mut Ui));

/// 面板：先画解析阴影，再用 GLASS_MATERIAL 贴模糊背景 + 内描边，最后在内部画内容
pub fn glass_panel<R>(ui: &mut Ui, r: Rect, radius: f32, tint: Color,
                      f: impl FnOnce(&mut Ui) -> R) -> R;
```

### 2.3 为什么不做"采样当前帧缓冲"

macroquad 里拿不到已渲染的当前 framebuffer。所以走
**「显式往 RT 渲染背景 → 降采样 → 模糊 → 当纹理用」**。
对本项目反而更合适：各页面的背景本来就是一张插图 / 一段动态背景，
渲染成本可控，而且可以**只在背景变化时重算一次**（切歌、切页时），
帧间零开销 —— 低端安卓机上这是能不能用的分界点。

### 7.2 踩过的坑（务必别再犯）

1. **`vec4` 没有 `.h` / `.w` 之外的宽高 swizzle。**
   写 `max(rect.w, rect.h)` 会让 GLSL 编译失败（`invalid character 'h' in swizzle`），
   静态 `Lazy<Material>` 首次初始化即 panic → 表现为**打开就白屏卡住**。
   正解：`rw = rect.z - rect.x; rh = rect.w - rect.y;`
   > 教训：**shader 编译失败 = 崩溃**，不是"没效果"。改动 shader 后一定要真启动一次。
2. **切换 render target 前必须 `gl.flush()`**（本项目 `game.rs:1958` 就是这么写的），
   否则在已打开的 pass 中间切目标可能让驱动卡住。
3. **`MaterialParams.textures` 是 `Vec<String>`**，不是 `(String, UniformType)`。
4. **着色器里的 `pos0` 是 UI 世界坐标，不是像素**（`RR_FRAGMENT` 的用法可证），
   所以 `rect` / `radius` 都要用 UI 单位。
5. **不要自己推 UV**。玻璃用「满屏画模糊背景 + 圆角遮罩裁切」，纹理朝向交给
   macroquad 的 `draw_texture` 通路，避免上下颠倒。
6. **不要动相机**。首页卡片在 `ui.with_gl(3D 倾斜)` / `ui.dx/dy` 里，
   `set_camera` + `abs_scope` 会让遮罩错位；现在只按 `ui.transform` 的平移量对齐四边形。
7. 新增 `PHIRA_NO_GLASS=1` 开关，玻璃出问题时可一键关掉做二分。

## 8.5 HUD 字体还原：排查结论（2026-09-24 深夜）

### 8.5.1 §8.2 的假设是错的

`hud_ui` / `judge_text_ui` **既不是裸 `ui.text`，也不是硬编码 `GAME_FONT`** —— 它们走的是第三条路：

```rust
// prpr/src/scene/game.rs:69
fn text_font(config: &Config) -> &'static LocalKey<RefCell<Option<TextPainter>>> {
    if config.phi_recorder_font { &GAME_FONT } else { &PGR_FONT }   // PGR_FONT = assets/phigros.ttf
}
```

用它的一共 5 处：`ui()`（分数/连击/准度/血条数字/曲名难度）、`debug_overlay`、
`hud_ui`、`judge_text_ui`（外加 `name_font` 管曲名/难度）。

所以默认渲染的是 **`assets/phigros.ttf`（原版 Phigros 字体）**，**不是 HarmonyOS Sans**。
`phi_recorder_font` 是 2026-09-16 的提交 `8d4f939` 加的，当时默认关。

### 8.5.2 真正漏在 harmonyos 上的只有 3 处

裸 `ui.text(...).draw()`（= 界面字体 harmonyos）而 phire 那边同位置是 font.ttf：

| `tweak_offset`（TweakOffset 模式） | 1221/1224 | 同上 |
| `overlay_ui`（练习模式时间轴、倒计时） | 888/925/936/947/962 | `game.rs:842/878/883/894/924` |

### 8.5.3 本轮改动（用户选 A：默认即 phire，保留退路）

### 8.5.4 ⚠️ 大坑：测试客户端的 `assets/font.ttf` 根本不是 Phi-Recorder 那份

而提交 `8367f8a` 用 `git add -f` 把 **Phi-Recorder 那份**强加进了仓库
（`git log -- assets/font.ttf` 只有这一个提交，且是 `Bin 0 -> 13449192`，即新增）。

> 而不是代码没接对。以后遇到同类问题先做这一步。

### 8.5.5 字号换算常量要跟着字体走（待办）

`IN_GAME_TEXT_H = 0.055` 是按 **phigros.ttf cap 高 0.688 em** 推出来的
（`0.08 × 0.688 = 0.05504`）。实测两套字体的 cap 高：

| 字体 | OS/2 sCapHeight | `0.08 × cap` |
|---|---|---|
| `assets/phigros.ttf` | 0.688 em | 0.0550 |
| `assets/font.ttf`（Phi-Recorder 那份） | **0.733 em** | **0.0586** |

差 **6.5%**。它影响 HUD 行距、HUD 描边偏移、判定文字外发光半径（都按"字高"算）。

### 8.8.1 真相：`scale_ratio` 被漏掉了

§8.2 写的「**字号：两边完全一致，不是问题**」是**错的**。

phire 的 `game.rs` 里有个硬编码常量：

   * `IN_GAME_TEXT_H = 0.055`（按 phigros.ttf cap 0.688 推的）**对 font.ttf 也成立，不用改**；

* **只作用于字号**：位置仍是 phire 的裸长度 ÷ 宽高比，ACC 的错开逻辑跟着分数实测盒高走，
  所以滑条滑动不会把版面搞乱；
* `PHIRE_SCALE_RATIO` 留在 `game.rs` 里作换算基准与注释对照（值 1.7778，

* `.anchor(1., 0.)` 的锚点是文本 **ascent 盒的顶**，字形顶还要再往下
  `(ascent − cap) ≈ 0.236 em`；
* 分数放大到 phire 的尺度后这 0.236 em 就是十几像素，于是 ACC 的盒顶落到了


### 8.9.1 连击文字改不动（`combo_label()`）


### 8.9.2 「本局不计入排行」不提示、但成绩其实没上传（`song.rs`）
